# Memo 录音实时总结 PRD

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 功能名称 | 录音实时转写与 AI 洞察 |
| 版本 | V1.0 |
| 产品定位 | 将课堂录音实时转化为可理解、可回听、可复习的知识记忆 |
| 核心场景 | 课堂听讲、讨论、讲座、口述整理 |
| 内容归属 | 原始录音、完整转写、AI 洞察和智能笔记共同组成一条 Memo 记忆 |

## 2. 需求背景

学生在课堂录音时，通常只能确认“是否录上”，无法同步判断老师讲了哪些重点、哪些内容容易出错。录音结束后，用户还需要从头回听，重点与原音频缺少对应关系。

本功能在录音过程中持续生成转写和阶段性洞察；录音完成后，对转写、洞察与音频时间轴进行最终校准。用户点击任一知识点或洞察，即可从对应的原始语音位置播放。

## 3. 需求目标

### 3.1 用户目标

- 录音时快速确认收音和转写是否正常。
- 不打断听课即可看到正在讲解的重点、易错点和待办。
- 录音结束后通过知识点直接回听原始讲解，无需拖动查找。
- 将录音自动沉淀为可搜索、可复习、可追溯原文原音的 Memo 记忆。

### 3.2 产品目标

- 降低长录音的回听和整理成本。
- 提升录音保存到 Memo 的比例及保存后再次打开率。
- 建立“原始语音—转写片段—知识点—总结”的可追溯关系。
- 为后续复习、错题、问答等功能提供结构化知识来源。

### 3.3 核心指标

- 有效录音率：录音时长 ≥ 10 秒且正常完成。
- 实时转写首屏延迟、稳定文本延迟及成功率。
- AI 洞察首次出现时间、洞察生成成功率。
- 录音完成后自动保存到记忆的成功率。
- 洞察/知识点点击回听率、跳转成功率。
- 保存后 7 天内录音记忆再次打开率。
- 因权限、网络、异常退出导致的录音失败率。

## 4. 功能范围

### 4.1 本期范围

- 开始、暂停、继续、完成和新建录音。
- 录音计时、收音波形及状态提示。
- 固定高度的实时转写区域。
- 老师/学生说话人区分。
- AI 洞察时间轴：重点、易错点、疑问、待办。
- 录音完成后的时间锚点校准和精准回听。
- 自动保存到记忆开关，默认开启。
- 保存成功 Toast、新录音入口和左侧录音列表。
- Memo 笔记内展示总结、知识点、完整转写和“查看原录音”。

### 4.2 暂不包含

- 录音过程中回放已录片段。
- 专业音频剪辑、降噪、变速编辑。
- 用户手工拖动知识点的时间锚点。
- 多设备同步录音或多人协同编辑。
- 对老师和学生进行真实身份识别；本期只做角色级区分。

## 5. 核心概念与数据关系

一条录音由以下对象组成：

| 对象 | 说明 |
|---|---|
| Recording | 原始音频、录音状态、时长、学科及创建时间 |
| Transcript Segment | 一段连续语音的文字、说话人、开始与结束时间 |
| Insight | AI 发现的重点、易错点、疑问或待办，可关联一个或多个转写片段 |
| Knowledge Point | 录音完成后整理出的稳定知识点，可关联多个非连续语音片段 |
| Memo Note | 面向复习的最终笔记，保存摘要、知识点、洞察和原录音入口 |

关系如下：

```text
原始录音
  └─ 转写片段（说话人 + start_ms + end_ms）
       ├─ 实时洞察（录音中为临时锚点）
       └─ 核心知识点（完成后可关联多个片段）
            └─ Memo 智能笔记
```

每个洞察必须保存 `source_segment_ids`，录音完成后再由这些片段计算最终 `anchor_start_ms` 和 `anchor_end_ms`。一个知识点可对应多段讲解，默认从“首次完整讲解”的片段开始播放，并允许用户切换其他相关片段。

## 6. 产品流程

```text
点击录音入口
→ 请求麦克风权限
→ 创建新的录音项并在左侧自动选中定位
→ 录音中：采集音频 + 实时转写 + 阶段性 AI 洞察
→ 可暂停 / 继续
→ 完成录音
→ 补齐尾部转写、说话人及标点
→ 校准洞察、知识点与音频时间轴
→ 生成摘要、知识点和知识框架
→ 按设置自动保存到 Memo / 等待用户手动保存
→ Toast 告知保存位置
→ 保持“开始新录音”按钮
```

## 7. 状态与操作规则

| 状态 | 可用操作 | AI 洞察与锚点表现 |
|---|---|---|
| 未开始 | 开始录音、关闭 | 无洞察 |
| 录音中 | 暂停、完成、最小化 | 持续生成总结；显示约略时间；不可点击回听 |
| 已暂停 | 继续、完成、最小化 | 保留已有洞察；不可点击回听 |
| 对齐处理中 | 等待、关闭后后台处理 | 显示处理状态；不可点击回听 |
| 已完成 | 播放、拖动、点击洞察回听、保存 | 时间锚点固定，可精准跳转 |
| 已保存 | 查看 Memo、播放、开始新录音 | 锚点可用；保存结果已进入 Memo |

关键规则：

1. 录音过程中总时长持续增长，转写文本和分段也可能被修正，因此洞察只用于实时理解，不提供播放跳转。
2. 录音结束后，系统对全文、说话人、片段边界和时间戳统一校准；校准完成后才开放锚点回听。
3. 暂停不结束本次录音，继续后仍写入同一条录音记录。
4. 完成录音后，“录音”主操作变为“开始新录音”。点击后左侧立即新增并选中新录音项，旧录音保留为历史记录。

## 8. 页面与交互设计

### 8.1 整体布局

录音以浅色弹窗浮层展示，不跳转到黑色独立页面。展开态采用三栏结构：

- 左侧：录音文件列表。
- 中间：录音状态、波形、计时和主操作。
- 右侧：`AI 洞察`与`实时转写`内容区。

弹窗右上角提供最小化按钮，图标与外部恢复/放大入口相互呼应。最小化后录音、计时、转写和洞察均继续运行。

### 8.2 左侧录音列表

- 开始录音时立即创建一条新录音项。
- 新录音项自动选中，并滚动到列表可见区域。
- 展示标题、日期、时长，以及录制中/已暂停等必要状态。
- 已保存录音只显示日期和时长，不显示“已形成记忆”。
- 完成后再次开始录音，旧录音保留，新录音成为当前选中项。

### 8.3 中间录音控制区

- 波形反馈当前是否正常收音。
- 显示累计录音时间。
- 录音中提供“暂停”和“完成”。
- 暂停后主按钮变为“继续录音”，同时保留“完成”。
- 完成后显示播放器；主操作固定为“开始新录音”。
- 不使用持续占位的“自动保存草稿”等说明性文案。

### 8.4 实时转写

- 转写框固定高度，内容在区域内部滚动，不推动整体布局。
- 临时识别文本与稳定文本需要有视觉差异，稳定后再进入正式段落。
- 说话人以图案区分：老师使用讲台/教师图案，学生使用学生/举手图案；同时保留文字标签以保证可访问性。
- 每段转写保存开始时间、结束时间和说话人。
- 无法确定角色时使用“说话人 1/2”，不强行标记老师或学生。

### 8.5 AI 洞察时间轴

AI 洞察直接展示在右侧内容区，不增加机器人 Logo、日期欢迎语或提问输入框。

顶部为固定的录音状态卡片：

- 录音中：显示当前录音标题、时长、AI 正在理解及洞察数量。
- 完成后：同一卡片切换为播放器，显示播放/暂停、进度和总时长。

下方以时间轴持续追加洞察，每条包含：

| 元素 | 说明 |
|---|---|
| 类型 | 重点 / 易错点 / 疑问 / 待办 |
| 时间 | 录音中显示“约 02:15”；完成后显示准确时间 |
| 标题 | 一句话表达结论，不写处理过程 |
| 说明 | 补充原因、公式、上下文或建议 |
| 状态 | 录音中显示“待对齐”；完成后变为可播放锚点 |

洞察内容原则：

- 直接输出结论，不展示“AI 正在分析了什么”的过程描述。
- 优先识别教师强调、重复解释、易混淆对比、明确作业要求和学生未解决的问题。
- 避免将普通转写句子换一种说法后当成洞察。
- 同一结论重复出现时合并，并关联多个录音片段。

### 8.6 锚点回听

- 仅在录音完成并校准后开放。
- 点击洞察或知识点，顶部播放器跳转到 `anchor_start_ms` 并自动播放。
- 当前播放对应的洞察高亮，时间轴自动滚动到可见区域。
- 默认从锚点前 2 秒开始，避免截断上下文；不得小于 0。
- 播放到该片段结尾后继续正常播放，不强制停止。
- 若知识点关联多段录音，展示“首次讲解”“补充说明”“例题”等片段入口。
- 锚点失效时提示“暂时无法定位，请从完整转写查看”，不可跳到错误位置。

### 8.7 保存到 Memo

- “自动保存到记忆”默认开启，用户可关闭。
- 开启时：录音完成、分析和对齐结束后自动保存。
- 关闭时：录音完成后提供明确的“保存到记忆”操作。
- 保存内容包括原始音频、完整转写、摘要、核心知识点、AI 洞察、学科和时间锚点。
- 保存成功后展示 Toast，文案明确到达位置，例如：`已保存到 Memo > 大学物理 > 笔记`。
- Toast 显示 5 秒后自动消失，也可手动关闭或点击“查看”。
- 回到 Memo 后，新生成内容在左侧学科及对应笔记卡片上显示绿色 `NEW`；用户首次打开后消失。

### 8.8 Memo 内的承接

录音生成的笔记采用右侧半屏抽屉，包含：

1. 内容摘要：只展示总结结论，不展示播放器和“已转为文字”等过程文案。
2. 核心知识点：按概念分组，展示相关录音片段数量。
3. AI 洞察：保留重点、易错点、疑问和待办。
4. 完整转写：按老师/学生分段展示。
5. 查看原录音：回到原录音播放器，并保留当前知识点对应的锚点。

“知识脉络”若与核心知识点内容重复则不单列；只有能表达概念先后、因果或依赖关系时才展示。

## 9. AI 处理逻辑

### 9.1 实时阶段

1. 音频流按短片段送入语音识别。
2. 识别结果根据停顿、说话人变化和语义形成 Transcript Segment。
3. 每积累一定稳定文本或检测到明确教学信号时触发洞察更新。
4. 洞察引用对应的 `segment_id`，时间只显示为近似值。
5. 实时阶段允许合并、修正和撤回低置信度洞察。

### 9.2 完成阶段

1. 对整段音频执行最终转写和说话人分离。
2. 修正标点、专有名词、公式及片段边界，同时保留原始转写版本。
3. 合并重复洞察，删除缺少录音证据的内容。
4. 基于引用片段生成最终锚点。
5. 生成内容摘要、核心知识点、知识关系和 Memo 笔记。

### 9.3 质量与置信度

- 低置信度转写需要标注，不得生成确定性知识结论。
- AI 洞察必须能追溯到至少一个转写片段。
- 涉及公式、数字、日期和作业要求时优先保留原话，并允许直接回听确认。
- 静音、噪声或无语义片段不生成洞察。

## 10. 异常与边界处理

| 场景 | 处理方式 |
|---|---|
| 麦克风权限拒绝 | 提供开启权限说明和重新授权，不创建空录音 |
| 实时转写中断 | 录音继续，提示“转写暂时中断”；结束后补转写 |
| AI 洞察生成失败 | 不影响录音和转写；完成后重新分析 |
| 网络中断 | 优先保留本地音频，恢复后续传、转写和对齐 |
| 无有效语音 | 不生成虚假总结，完成时提示未识别到清晰内容 |
| 暂停期间 | 不累计有效录音时长，不生成转写或洞察 |
| 保存失败 | 保留本地记录和分析结果，提供重试 |
| 用户关闭弹窗 | 录音中需要二次确认；最小化不停止录音 |
| 页面刷新/关闭 | 有未完成录音时提示；尽可能恢复本地临时记录 |
| 超长录音 | 达到上限前提示；到达上限自动完成并进入处理 |

## 11. 埋点设计

### 11.1 公共字段

`user_id`、`session_id`、`recording_id`、`entry_source`、`subject_id`、`course_id`、`recording_phase`、`network_type`、`client_type`、`timestamp`。

### 11.2 关键事件

| 事件名 | 触发时机 | 关键属性 |
|---|---|---|
| `recording_entry_clicked` | 点击录音入口 | `entry_source` |
| `recording_started` | 成功开始采集 | `permission_result` |
| `recording_paused` | 点击暂停 | `elapsed_ms` |
| `recording_resumed` | 点击继续 | `pause_duration_ms` |
| `recording_completed` | 点击完成或达到上限 | `duration_ms`, `complete_reason` |
| `recording_new_started` | 完成后开始新录音 | `previous_recording_id` |
| `transcript_first_result` | 首次出现转写 | `latency_ms` |
| `transcript_segment_stable` | 一段转写稳定 | `segment_id`, `speaker`, `confidence` |
| `insight_generated` | 新增或更新洞察 | `insight_id`, `insight_type`, `latency_ms`, `confidence` |
| `insight_alignment_completed` | 录音完成并完成锚点校准 | `insight_count`, `success_count`, `duration_ms` |
| `insight_anchor_clicked` | 点击洞察回听 | `insight_id`, `anchor_start_ms`, `recording_status` |
| `playback_seek_completed` | 播放器成功跳转 | `target_ms`, `actual_ms`, `deviation_ms` |
| `auto_save_setting_changed` | 修改自动保存设置 | `enabled` |
| `recording_memory_saved` | 保存到 Memo 成功 | `auto_save`, `subject_id`, `note_id` |
| `recording_save_toast_clicked` | 点击保存成功 Toast | `action`, `note_id` |
| `recording_memory_opened` | 打开录音生成的 Memo | `source`, `is_new` |

### 11.3 核心漏斗

```text
点击录音入口
→ 成功开始录音
→ 产生有效转写
→ 产生 AI 洞察
→ 完成录音
→ 完成时间锚点校准
→ 保存到 Memo
→ 点击洞察回听 / 再次打开记忆
```

## 12. 验收标准

1. 开始新录音后，左侧立即新增、选中并定位到该录音项。
2. 录音中可以暂停、继续、完成；暂停后计时和内容生成停止。
3. 实时转写区域高度固定，新内容在区域内滚动。
4. 老师与学生在完整转写中具有不同图案和文字标签。
5. 录音中可看到 AI 洞察，但所有时间锚点不可点击。
6. 录音完成并校准后，洞察时间变为准确值且可点击播放。
7. 点击洞察后播放器误差应控制在产品约定范围内，建议不超过 500ms。
8. 自动保存默认开启，关闭后不得未经用户操作写入 Memo。
9. 保存成功 Toast 明确告知 Memo 内的具体位置，5 秒后消失。
10. 保存后 Memo 左侧学科与笔记卡片显示绿色 `NEW`。
11. Memo 中可查看相同的总结和知识结构，并可返回原录音原文原音。
12. 完成录音后始终保留“开始新录音”操作；新录音不会覆盖上一条记录。

## 13. 迭代建议

- V1：实时转写、阶段性洞察、完成后锚点回听、保存到 Memo。
- V1.1：用户标记重点、手动纠正说话人、洞察反馈。
- V1.2：跨录音知识聚合、自动生成复习卡和相关练习。
- V2：个性化洞察策略，根据学科、课程和用户薄弱点动态调整。
