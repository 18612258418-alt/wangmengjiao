# 多格式上传、解析与挂靠架构规则

## 1. 核心原则

上传不是一个“文件选择后调用一次 AI”的动作，而是一条可恢复、可追踪、可追加的内容处理流水线：

```text
接收文件
→ 文件校验
→ 建立上传任务
→ 保存原文件
→ 类型识别
→ 内容预处理
→ 分段/分页解析
→ 结构化整理
→ 去重判断
→ 课程与学期挂靠
→ 用户确认
→ 保存内容
```

必须遵守：

1. 原文件先保存，AI 解析失败不能导致原文件丢失。
2. 每个文件、每一页、每个片段都有独立状态。
3. 批量上传必须排队并限制并发，禁止把所有文件同时请求模型。
4. 新内容默认追加，禁止覆盖之前的非重复内容。
5. 去重只删除真正重复的内容，不能根据标题相似就覆盖。
6. 解析、挂靠和保存是三个独立步骤，任一步失败都可以单独重试。

## 2. 支持的输入类型

### 图片

- jpg / jpeg
- png
- webp
- heic / heif
- gif（取静态帧或关键帧）
- bmp / tiff
- 手机拍照、截图、扫描件、圈画图片

处理要求：

- 自动纠正 EXIF 方向；
- 超大图片等比压缩，不裁掉正文；
- 保留原图用于预览；
- OCR 与视觉理解分开，OCR 失败时仍可走视觉模型；
- 多张连续图片支持识别为同一组资料；
- 圈画图片必须同时保存原图、圈画区域和解析结果。

### PDF

- 文本型 PDF
- 扫描型 PDF
- 图文混合 PDF
- 多页课件、论文、试卷和电子书

处理要求：

- 优先提取文字层；
- 无文字层的页面逐页转图片识别；
- 按页建立 `pageNumber`，不得只解析第一页；
- 大 PDF 分批处理，允许先展示已完成页面；
- 保留目录、章节、页码和原文位置；
- 点击来源可直接打开对应 PDF 页。

### Office 与表格

- doc / docx
- ppt / pptx
- xls / xlsx
- csv
- txt / md

处理要求：

- Word 保留标题层级、段落和表格；
- PPT 按页解析标题、正文、备注和图片；
- Excel 识别工作表、合并单元格、表头和数据区域；
- 课表文件走专用课表解析器，不与普通学习资料混用；
- 一个 Excel 含多个学期或多个工作表时分别识别和保存。

### 网页与链接

- 普通网页
- 公开文章
- 在线 PDF
- 视频页面

处理要求：

- 保存原始 URL、页面标题和抓取时间；
- 优先抽取正文，过滤导航、广告和评论噪声；
- 网页发生变化时保留上传时版本；
- 无法访问时保留链接并允许稍后重试；
- 点击来源打开原网页，不显示“查看原图”。

### 音频

- mp3 / m4a / wav / aac / flac / ogg / opus / amr

处理要求：

- 大文件分片上传；
- 长音频按时间切片转写；
- 保留时间戳和说话人；
- 转写结果按课程、章节和知识点整理；
- 点击来源可跳到对应时间；
- 单片失败只重试该片，不重跑整段音频。

### 视频

- mp4 / mov / m4v / webm / avi

处理要求：

- 音轨转写；
- 按镜头或固定时间提取关键帧；
- 联合字幕、语音和画面理解；
- 截图和用户标记必须记录视频时间；
- 点击来源跳转到对应时间点；
- 长视频分段解析并逐段返回结果。

## 3. 上传任务模型

每个文件创建独立任务：

```ts
type UploadJob = {
  jobId: string;
  batchId: string;
  fileId: string;
  fileName: string;
  fileType: string;
  fileSize: number;
  status:
    | "queued"
    | "uploading"
    | "stored"
    | "preprocessing"
    | "parsing"
    | "waiting_confirmation"
    | "saved"
    | "partially_failed"
    | "failed";
  progress: number;
  currentStep: string;
  retryCount: number;
  errorCode?: string;
  errorMessage?: string;
};
```

多页和长媒体建立子任务：

```ts
type UploadPart = {
  partId: string;
  jobId: string;
  pageNumber?: number;
  startTime?: number;
  endTime?: number;
  status: UploadJob["status"];
  contentId?: string;
};
```

禁止用一个布尔值表示整个批次成功或失败。

## 4. 批量上传与并发

- 文件选择后立即为全部文件建立队列。
- 图片视觉解析默认并发数为 1；服务稳定时最多为 2。
- PDF 页面解析、音视频切片解析必须有并发上限。
- 同一用户的批次保持顺序，但单个文件失败不阻塞后续文件。
- 页面关闭或刷新后，任务状态应可恢复。
- 已完成结果立即可见，不必等待整个批次结束。
- 界面显示“第 X/Y 个文件”和文件内部进度。
- 禁止同时向模型提交大量 Base64 文件造成网关、内存或额度超限。

## 5. 预处理规则

### 图片

1. 读取原图；
2. 修正方向；
3. 生成预览图；
4. 在不影响文字识别的前提下压缩；
5. 首次失败时降低尺寸和质量自动重试；
6. 原图始终保留，不用压缩图替换原图。

### PDF

1. 检查文字层；
2. 提取目录和页数；
3. 文本页走文本模型；
4. 扫描页走 OCR/视觉模型；
5. 图文页合并文本与视觉结果；
6. 按章节聚合，但保留页级来源。

### 音视频

1. 校验编码和时长；
2. 必要时转码；
3. 分片；
4. 音频转写；
5. 视频提取关键帧；
6. 对齐时间戳后再生成结构化知识。

## 6. 超时、重试与降级

可重试错误：

- 请求超时；
- 429 限流；
- 502 / 503 / 504；
- 模型暂时不可用；
- 网络中断；
- 单页 OCR 失败。

重试规则：

1. 首次失败后自动重试；
2. 使用指数退避；
3. 图片重试时降低分辨率；
4. PDF、音视频只重试失败的页面或片段；
5. 达到上限后进入“可手动重试”，不得删除任务。

不可静默重试的错误：

- 文件损坏；
- 文件加密且无密码；
- 格式不支持；
- 文件内容为空；
- 用户权限不足。

降级顺序：

```text
原生文本提取
→ OCR
→ 视觉理解
→ 保存原文件并标记“待解析”
```

AI 不可用时，允许用户先保存和挂靠原文件，不能阻塞整个上传流程。

## 7. 去重与追加保存

每个来源计算：

- 文件哈希；
- 页面/片段哈希；
- 正文指纹；
- 来源位置；
- 用户标记区域指纹。

只有以下条件足够一致时才判定为重复：

```text
同一原文件
+ 同一页或同一时间片
+ 同一内容区域
+ 正文指纹一致
```

以下情况必须保留为多篇内容：

- 同一知识点的不同笔记；
- 同一书籍的不同页；
- 同一视频的不同时间片；
- 同一页上的不同圈画区域；
- 不同同学或不同时间产生的笔记；
- 标题相同但正文不同；
- AI 总结相似但原始来源不同。

禁止用标题、摘要或知识点名称相似作为覆盖依据。

## 8. 课程与学期挂靠

挂靠所需上下文：

- 当前学期；
- 当前课程；
- 课表中的课程名称、教师和时间；
- 文件名；
- 文件正文；
- 上传入口；
- 用户手动选择；
- 前后上传资料的上下文。

挂靠优先级：

1. 用户明确选择；
2. 从当前课程页面上传；
3. 课程 ID 和学期 ID 明确匹配；
4. 文件内容与课表课程匹配；
5. 无法确定则进入“待归类”。

规则：

- 同名课程跨学期隔离。
- 一份资料可以挂靠多个知识点。
- 一份跨课程资料可以挂靠多门课程，但只保存一个原文件。
- 用户修改挂靠后，侧边栏课程数量和知识内容立即重新计算。
- 解析失败的文件可以先挂靠课程，但不计入“已成功解析内容”；原文件仍可查看。

## 9. 用户确认

解析完成后至少允许用户确认：

- 标题；
- 内容类型；
- 学期；
- 课程；
- 知识点；
- 来源范围；
- 是否与已有内容合并。

系统可以推荐，但不能在低置信度下直接覆盖或错误归类。

## 10. 状态与界面文案

允许展示给用户的状态：

- 等待上传
- 正在上传
- 正在读取文件
- 正在识别第 X/Y 页
- 正在转写第 X/Y 段
- 正在整理内容
- 等待确认
- 已保存
- 部分内容未识别
- 解析失败，可重试

禁止直接展示后台异常堆栈、模型名称、函数错误码和内部接口路径。

错误提示必须说明：

1. 哪个文件失败；
2. 失败在哪一步；
3. 已成功保留了什么；
4. 用户下一步能做什么。

## 11. 数据安全

- API 密钥只保存在服务端。
- 上传接口校验 MIME、扩展名和实际文件头。
- 文件名不能直接作为服务器路径。
- 限制单文件、单批次和单用户总容量。
- 扫描恶意文件。
- 用户删除原文件时明确告知关联内容影响。
- 日志中不得记录完整 Base64、密钥和用户隐私正文。

## 12. 可观测性

每个任务记录：

- `batchId`
- `jobId`
- `fileId`
- 文件类型和大小
- 各阶段耗时
- 模型请求次数
- 重试次数
- 最终状态
- 标准化错误码

出现“全部失败”时可以区分：

- 前端未发出请求；
- 上传网关失败；
- 文件预处理失败；
- 模型限流；
- 模型超时；
- 返回格式解析失败；
- 保存失败。

## 13. 验收场景

必须验证：

1. 单张图片成功解析和挂靠；
2. 一次上传 10 张图片，按队列逐张完成；
3. 其中一张失败，其他图片继续处理；
4. 多个 PDF 同时上传；
5. 100 页 PDF 分页处理并可部分完成；
6. 扫描 PDF 与文本 PDF 都可处理；
7. 多个音频按文件和时间片显示进度；
8. 多个视频按转写和关键帧联合解析；
9. 上传相同文件提示重复，不重复保存；
10. 上传同知识点的不同文件，全部保留；
11. 刷新页面后任务可恢复；
12. AI 不可用时仍能保存原文件并稍后重试；
13. 学期和课程挂靠正确；
14. 新内容不会覆盖上一篇非重复笔记。
